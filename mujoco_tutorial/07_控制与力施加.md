## 7.1 控制链路的全貌

你的控制器（Python 函数）和物理引擎（MuJoCo）之间只有一座桥：**`data.ctrl`**。

```
控制器算法 ──► data.ctrl ──► 执行器(actuator) ──► 广义力(qfrc_actuator) ──► 动力学求解 ──► 状态更新
```

每个执行器对应 `ctrl` 的一个分量。每步仿真**先**设置 `ctrl`，**再** `mj_step`：

```python
while data.time < T:
    data.ctrl[:] = controller(model, data)   # 控制器算出控制输入
    mujoco.mj_step(model, data)
```

**ctrl 的含义取决于执行器类型**（第 2 章 2.7 节）：

| 执行器 | ctrl 的含义 | 转换规则 |
|---|---|---|
| `motor` | 直接力矩/力 | τ = ctrl × gear |
| `position` | 目标角度/位置 | 内置 PD（kp 比例 + damping 隐式阻尼） |
| `velocity` | 目标角速度 | 内置速度环 |

## 7.2 三种控制写法的对比（阶段 6 的核心理解）

### 写法 A：内置 position 执行器（配置即控制）

```xml
<actuator>
  <position name="p1" joint="j1" kp="100" damping="5" ctrlrange="-3.14 3.14"/>
</actuator>
```

```python
data.ctrl[data.actuator("p1").id] = 1.0   # 目标角 1.0 rad，剩下的交给引擎
```

**实测细节**（3.11）：position 执行器的比例项 `kp·(ctrl − q)` 会体现在 `data.qfrc_actuator` 中，但 **`damping` 参数产生的阻尼是隐式处理的**（不体现在 qfrc_actuator 里，直接在积分器里起作用）。所以：

- 用 `qfrc_actuator` 做动力学验证时，position 执行器**只**显示比例部分——这是正常的，不是 bug。
- 想直观对比"公式 τ = kp·e − kd·ė"与仿真，用手写 PD（写法 B）。

### 写法 B：motor 执行器 + 手写 PD（阶段 6 主线）

```xml
<actuator>
  <motor name="tau1" joint="j1" gear="1.0"/>
</actuator>
```

```python
def pd_controller(model, data, q_des, kp=50.0, kd=5.0):
    """手写 PD：力矩 = kp·误差 − kd·速度（全显式，方便逐项对照教材公式）"""
    e = q_des - data.qpos
    edot = -data.qvel
    return kp * e + kd * edot      # 符号按你的教材约定

data.ctrl[:] = pd_controller(model, data, q_des=1.0)
mujoco.mj_step(model, data)
```

**为什么阶段 6 建议手写 PD 而不是用 position 执行器**：因为你要"理论公式 → 代码 → 仿真数据"三者对照。position 执行器把 PD 藏在了引擎内部（阻尼还不可见），你无法逐项验证；手写 PD 的 kp、kd、力矩每一项都在你的代码里，可以和教材公式、仿真响应一一对上。**内置 position 执行器留给阶段 7 的轨迹跟踪**（它本来就是干这个的：每步给目标角，天然支持连续轨迹）。

### 写法 C：计算力矩控制 CTC（阶段 6 进阶）

第 6 章 6.5 节已给出：τ = M·(q̈_des + Kp·e + Kd·ė) + b，其中 M、b 分别来自 `mj_fullM`、`qfrc_bias`。

## 7.3 单摆 PD 控制完整示例（实测可运行）

```python
"""手写 PD 让单摆摆到目标角并稳住。"""
import mujoco
import numpy as np

xml = """
<mujoco model="pendulum_ctrl">
  <compiler angle="radian"/>
  <option timestep="0.002"/>
  <worldbody>
    <body name="base" pos="0 0 1.0">
      <geom type="box" size="0.1 0.1 0.1"/>
    </body>
    <body name="pendulum" pos="0 0 1.0">
      <joint name="pivot" type="hinge" axis="0 1 0" damping="0.02"/>
      <geom type="capsule" size="0.02" fromto="0 0 0 0 0 -0.5" mass="1.0"/>
    </body>
  </worldbody>
  <actuator>
    <motor name="tau" joint="pivot" gear="1"/>
  </actuator>
</mujoco>
"""
model = mujoco.MjModel.from_xml_string(xml)
data = mujoco.MjData(model)

q_des = 1.0        # 目标角
kp, kd = 80.0, 12.0
t, q_hist = [], []

while data.time < 5.0:
    e = q_des - data.qpos[0]
    tau = kp * e - kd * data.qvel[0]       # 手写 PD
    data.ctrl[0] = tau
    mujoco.mj_step(model, data)
    t.append(data.time); q_hist.append(data.qpos[0].copy())

import matplotlib.pyplot as plt
plt.plot(t, q_hist, label="q(t)")
plt.axhline(q_des, ls="--", c="r", label="target")
plt.xlabel("t [s]"); plt.ylabel("q [rad]"); plt.legend()
plt.show()
```

画出的曲线就是标准二阶响应（你第 0 阶段学过的欠阻尼/过阻尼形状）——**阶段 6 的起点就是把你第 0 阶段的二阶系统知识搬到这个闭环上**。

调试技巧：kp 决定刚度（最终精度），kd 决定阻尼（震荡程度）。先大 kd 防震荡，再调 kp 保精度。这就是第 0 阶段 zeta、omega_n 的现场版。

## 7.4 施加外力：xfrc_applied 与 qfrc_applied

两种施加"外力"的途径（用途不同，**容易混淆，实测区分**）：

| 接口 | 含义 | 用途 |
|---|---|---|
| `data.qfrc_applied` | 直接施加**广义力**（关节空间的力） | 给特定关节加力矩（替代执行器做测试） |
| `data.xfrc_applied` | 施加**笛卡尔力/力矩**到刚体（世界系） | 推机器人的某个部位——扰动、风力 |
| `mj_applyFT(m, d, F, T, point, body, tau_out)` | 笛卡尔力 → 输出**等效广义力** | 阶段 4 力域验证 τ=JᵀF |

```python
# 在刚体"pendulum"上施加世界系力 (0,0,10)N + 力矩 (0,0,0)
data.xfrc_applied[model.body("pendulum").id, :6] = [0, 0, 10, 0, 0, 0]

# 给关节 0 直接加 2 N·m 广义力矩
data.qfrc_applied[0] = 2.0

# 每步要清零！xfrc_applied 不会自动消失
# 正确模式：循环里每次都重新赋值（或不用时置 0）
```

**实测重要提醒**：3.11 中设置 `xfrc_applied` 后，`qfrc_applied` 字段**不会**显示等效广义力（保持 0）——映射发生在约束求解内部。想拿到"外力对应的关节力矩"，用 `mj_applyFT` 的第 7 个输出参数（第 5 章 5.5 节，实测与 JᵀF 完全一致）。

**阶段 6 扰动实验**：人形站稳后推一把 → `data.xfrc_applied[body_id] = [Fx, 0, 0, 0, 0, 0]` 施加 1~2 步再清零（模拟瞬时推击），观察是否回稳。或在 Simulate/viewer 里用 `viewer.perturb` 交互式推（第 4 章）。

## 7.5 阶段 7 轨迹跟踪的 API：position 执行器

阶段 7 的轨迹跟踪：先规划五次多项式轨迹 q_des(t)，再让机器人跟踪。两条路：

**路线 1（推荐起步）：position 执行器直接吃轨迹**

```python
def quintic_trajectory(t, t0, t1, q0, q1):
    """五次多项式（你阶段 7 要自己写，这里只是调用示例）"""
    ...  # 你的实现

data.ctrl[:] = quintic_trajectory(data.time, t0, t1, q0, q1)
mujoco.mj_step(model, data)
```

每步把轨迹值写进 ctrl（position 执行器 ctrl=目标角），引擎内置 PD 完成跟踪。**注意**：ctrl 是"分段常数"——每个积分步内保持不变，这本身就是零阶保持器的离散化（教材里的采样保持，你可以在误差分析里讨论它）。

**路线 2：motor + 手写 PD 跟踪**（进阶，能控制阻尼特性）：τ = kp·(q_des − q) + kd·(q̇_des − q̇)，其中 q̇_des 来自轨迹导数——**跟踪问题必须用速度误差**，只用位置误差会滞后（经典错误，阶段 7 重点体会）。

## 7.6 控制实验的调试三板斧

1. **先无重力**：`<option gravity="0 0 0"/>` 或 `model.opt.gravity[:] = 0`，把动力学问题和控制问题分离（阶段 6 CTC 实验强烈建议先这么做）。
2. **看 ctrl 和力矩**：打印 `data.ctrl`、`data.qfrc_actuator`，确认"你给的"和"引擎用的"一致（position 执行器注意 7.2 的实测细节）。
3. **看能量**：`data.energy` 是动能+势能，PD 控制下应单调收敛——比肉眼看动画可靠。

## 本章小结：阶段 6、7 的 MuJoCo API 对照表

| 实验 | 执行器 | 每步写入 | 调试读数 |
|---|---|---|---|
| 阶段 6 手写 PD | motor | τ = kp·e + kd·ė | qpos 曲线、energy |
| 阶段 6 CTC | motor | τ = M·(q̈+kp·e+kd·ė)+b | 与 mj_inverse 对比 |
| 阶段 6 阻抗控制 | motor | τ = Jᵀ·K·Δx + ... | mj_applyFT 验证力映射 |
| 阶段 7 轨迹跟踪 | position 或 motor | q_des(t) 或 PD 力矩 | 轨迹误差 e(t) |
