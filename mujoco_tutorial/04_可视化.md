## 4.1 三个可视化工具的定位

| 工具 | 用途 | 什么时候用 |
|---|---|---|
| **Simulate 程序**（`python -m mujoco.viewer`） | 交互式"看模型、拖拽物体" | 建模后检查 XML、演示初始位形 |
| **viewer.launch_passive** | Python 脚本驱动仿真 + 实时窗口 | 你的实验主体：控制器跑起来时看效果 |
| **Renderer（离屏渲染）** | 不弹窗，把画面渲染成图片数组 | 批量录数据、训练 RL 时记录画面、保存视频 |

## 4.2 Simulate 程序（3.11 现状）

第 1 章讲过：**3.11 移除了 `mujoco.simulate` 模块**，现在用：

```bash
python -m mujoco.viewer --mjcf=pendulum.xml    # 带模型启动
python -m mujoco.viewer                        # 空窗口，把 .xml 拖进来
```

Simulate 里有完整的物理循环，可以暂停、步进（F1 单步）、拖拽扰动——它是"模型体检工具"，不是编程接口。

## 4.3 viewer.launch_passive：脚本驱动 + 实时窗口（最重要）

这是你学习计划里所有"看效果"实验的标准写法（`demo_mujoco.py` 就是这个模式）：

```python
import time
import mujoco
import mujoco.viewer

model = mujoco.MjModel.from_xml_path("pendulum.xml")
data = mujoco.MjData(model)

with mujoco.viewer.launch_passive(model, data) as viewer:
    # 仿真循环：直到用户关窗
    while viewer.is_running():
        step_start = time.time()

        # —— 在这里做控制：写 data.ctrl 等（第 7 章）——
        data.ctrl[:] = controller(data)
        # —— 控制写在这里 ——

        mujoco.mj_step(model, data)     # 推进物理
        viewer.sync()                   # 把新状态同步给渲染线程

        # 让仿真速度接近真实：睡到本步应耗的时间
        time_until_next_step = model.opt.timestep - (time.time() - step_start)
        if time_until_next_step > 0:
            time.sleep(time_until_next_step)
```

**要点**：

1. `viewer.is_running()` 在用户关闭窗口后返回 False，循环自然退出。
2. `viewer.sync()` 每步调用——忘了它窗口会冻结（卡在第一步的画面）。
3. 加 `time.sleep` 是为了"实时"。**做阶段 5、6 的控制器调试时，实时速度很有用**；纯跑数据不要睡（模式 A 更快）。
4. `launch_passive` 在独立线程渲染，你的主线程跑物理——所以控制器代码没有渲染开销干扰。
5. 退出用 `with` 语句，自动清理线程。

### 常用 viewer 接口

```python
with mujoco.viewer.launch_passive(model, data) as viewer:
    viewer.cam.distance = 5.0          # 相机距离
    viewer.cam.azimuth = 90            # 水平角（度）
    viewer.cam.elevation = -30         # 俯仰角
    viewer.cam.lookat[:] = [0, 0, 0.5] # 注视点

    # 渲染选项（渲染是否显示坐标轴、碰撞几何等）
    viewer.opt.flags[mujoco.mjtVisFlag.mjVIS_CONTACTPOINT] = True   # 显示接触点

    # 屏幕文字覆盖（调试信息）
    viewer.set_texts([(mujoco.mjtFontScale.mjFONTSCALE_150,
                       mujoco.mjtGridPos.mjGRID_TOPLEFT,
                       f"t = {data.time:.3f} s", f"q = {data.qpos.round(3)}")])
```

`viewer.perturb` 可以在代码里施加扰动（对应 Simulate 的 CTRL 拖拽），阶段 6 做扰动实验（如"站稳后推一把"）可用：

```python
viewer.perturb.active = 1
viewer.perturb.select = model.body("pendulum").id   # 选中的 body
viewer.perturb.force[:] = [0, 0, 10]                # 施加的力
```

## 4.4 viewer.launch：托管模式（简单场景）

```python
mujoco.viewer.launch(model, data)
```

`launch` 会在**主线程**里自己跑物理循环并阻塞，直到关窗。适合"就想看看这个模型"的场景。**不要**在需要精细控制的实验里用它——循环不受你控制，无法插自己的控制器代码（`launch_passive` 才是控制实验的正解）。

`launch_from_path`（3.9+）：直接给模型文件路径：

```python
mujoco.viewer.launch_from_path("pendulum.xml")
```

## 4.5 Renderer：离屏渲染（不弹窗出图片）

阶段 8 的 RL 需要"画面"作为观测或录像，用 `mujoco.Renderer`（**实测可用**）：

```python
import mujoco
import numpy as np

model = mujoco.MjModel.from_xml_path("pendulum.xml")
data = mujoco.MjData(model)

# 创建渲染器：指定输出分辨率
renderer = mujoco.Renderer(model, height=480, width=640)

# 相机：默认自由视角
camera = mujoco.MjvCamera()
camera.distance = 3.0

# 每帧：更新场景 -> 渲染 -> 得到 RGB 数组
renderer.update_scene(data, camera=camera)
img = renderer.render()          # shape (480, 640, 3)，uint8

# 保存成图片
import imageio  # 需要 pip install imageio
imageio.imwrite("frame_000.png", img)

# 录视频：循环里收集帧
frames = []
for i in range(100):
    mujoco.mj_step(model, data)
    renderer.update_scene(data, camera=camera)
    frames.append(renderer.render())
imageio.mimsave("sim.mp4", frames, fps=50)   # imageio-ffmpeg 提供 mp4 编码
```

要点：

- `Renderer` 不需要弹窗，**可以在没有显示器的情况下渲染**（支持 EGL/OSMesa 后端）。
- 用模型里定义的相机：`camera = mujoco.MjvCamera(); mujoco.mjv_defaultFreeCamera(model, camera)` 后 `renderer.update_scene(data, camera=camera, scene_option=...)`。
- RL 里每步渲染很贵，**只在需要时**渲染（比如每 10 步存一帧），别在训练主循环里无条件渲染。

## 4.6 相机控制速查

模型里定义固定相机（XML）：

```xml
<worldbody>
  <camera name="side" pos="3 0 1.5" xyaxes="1 0 0  0 1 0"/>  <!-- 位置 + 朝向 -->
</worldbody>
```

Python 端切换视角：

```python
# 用模型里的相机
viewer.cam.type = mujoco.mjtCamera.mjCAMERA_FIXED
viewer.cam.fixedcamid = model.camera("side").id

# 或自由视角（默认）
viewer.cam.type = mujoco.mjtCamera.mjCAMERA_FREE
```

阶段 2~4 的机械臂实验，从正上方（azimuth=0, elevation=-90）看 xy 平面臂最直观。

## 4.7 常见问题（Windows 实测）

| 问题 | 原因 / 处理 |
|---|---|
| 窗口出现但画面不动 | 忘调 `viewer.sync()`（passive 模式） |
| 脚本卡住不退出 | `launch` 模式会阻塞到关窗；确认有 `with` 块或 `viewer.close()` |
| 渲染报 GLFW 错误 | 无头环境（远程/SSH）用 Renderer 而不是 viewer |
| 视频里只有黑屏 | 没调 `renderer.update_scene` 就直接 render |
| imageio 报错 | `pip install imageio imageio-ffmpeg`（gymnasium 渲染也缺它） |
