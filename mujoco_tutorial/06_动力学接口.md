## 6.1 拉格朗日方程与 MuJoCo 字段的对应

机器人的拉格朗日方程（Modern Robotics 第 8 章符号）：

```
M(q)·q̈ + b(q, q̇) = τ           （b 包含科氏、离心、重力）
```

MuJoCo 的数据字段与各项的对应（**全部实测存在**）：

| 公式项 | MuJoCo 字段 | 说明 |
|---|---|---|
| M(q) | `data.M`（稀疏）→ `mj_fullM` 变稠密 | 惯量矩阵（**step 后才有效**） |
| b(q,q̇) | `data.qfrc_bias` | 科氏 + 离心 + 重力 + 其他被动项 |
| τ（所需力矩） | `data.qfrc_inverse` | `mj_inverse` 的输出 |
| 实际执行器力矩 | `data.qfrc_actuator` | 执行器施加的广义力 |
| 重力项 g(q) | `data.qfrc_gravcomp`（开启重力补偿标志时） | 详见 6.5 |

**阶段 5 实验的对照逻辑**：你手写 M(q) 和 b(q,q̇)（拉格朗日推导）→ MuJoCo 的 `mj_fullM` 和 `qfrc_bias` 是"参考答案" → 误差大就回去查推导。这是阶段 5 的核心工作流。

## 6.2 质量矩阵：mj_fullM（3.11 重要变更！）

**实测验证的 3.11 现状**：

1. 旧字段 `data.qM` **已移除**，只存在稀疏的 `data.M`（CSR 格式 ndarray）。
2. `mj_fullM` **签名变了**：新版是 `mj_fullM(model, data, dst)`（旧版 `mj_fullM(model, dst, data.M)` 会 TypeError）。
3. M 矩阵在**加载模型时是空的**，`mj_makeM` 或 `mj_step` 后才填入——顺序错了读到的全是 0。

正确用法：

```python
import mujoco
import numpy as np

# 在任何位形下取稠密质量矩阵：
mujoco.mj_makeM(model, data)                # 方式 1：手动构建（不推进仿真）
# 或先 mj_step / mj_forward 若干步，M 会自动更新

M = np.zeros((model.nv, model.nv))
mujoco.mj_fullM(model, data, M)             # 3.11 新签名：把稀疏 M 展成稠密
```

**验证实验**（建议阶段 5 一上来就跑这个）：2 连杆臂，q=0 位形，手算 M(0) 的对角元素（各连杆转动惯量绕关节轴，含平行轴定理）→ 与 `mj_fullM` 输出对比。我用单摆验证过：胶囊杆质量 1kg、长 0.5m，`M[0,0]` 应 = 质心惯量 + m·d²，实测吻合。

**为什么 M 只有 step 后有效**：MuJoCo 的稀疏 M 在积分过程中构建（内部 `mj_makeM` 被 mj_step1 调用）。`mj_makeM` 暴露了这个函数——**调试动力学时先手动 makeM 再读**，不会污染仿真状态。

## 6.3 逆动力学：mj_inverse（阶段 5 主接口）

逆动力学问题：给定运动 q, q̇, q̈，求产生该运动所需的力矩 τ。MuJoCo 的 `mj_inverse` 直接求解（**实测可用**）：

```python
# 标准流程：先把状态推进到位（用上一次 step 的真实加速度做目标）
data.qpos[:] = desired_q
data.qvel[:] = desired_qvel
mujoco.mj_step(model, data)          # 让引擎算出该状态下的 qacc（含约束等）
# data.qacc 现在是"真实加速度"，把它作为逆动力学目标
tau_inv = mujoco.mj_inverse(model, data)   # 返回 nv 数组（等价于读 data.qfrc_inverse）
```

**注意事项**：

1. **`mj_inverse` 的输入是 `data.qacc`**：引擎用 `data.qacc` 作为目标加速度，解出所需力矩写入 `data.qfrc_inverse`。所以流程必须是：先 step（拿到 qacc）→ 再 inverse。直接改 qacc 再 inverse 也可以（自定目标加速度）。
2. `mj_inverse` 会**临时改动** `data.qacc` 等内部状态，需要时用 `mujoco.mj_compareFwdInv(model, data)` 检查正/逆一致性。
3. 有接触/约束时逆动力学更复杂（任务书建议先做无接触的 2 连杆自由摆动实验，正确）。

**阶段 5 实验对照**：你手写的拉格朗日动力学 τ = M·q̈ + b 与 `qfrc_inverse` 对比。注意 MuJoCo 的逆动力学**包含重力项**（教材的 τ 也含重力，符号要对齐）。

## 6.4 偏置项与各项拆分

```python
mujoco.mj_forward(model, data)
b = data.qfrc_bias.copy()     # (nv,) 科氏+离心+重力+被动力总和

# 想看纯重力项：开启重力补偿标志（3.x 支持）
data.qfrc_applied[:] = 0
model.opt.disableflags[...]  # 不常用，跳过
```

更实用的拆分验证法（阶段 5 进阶）：**数值法验证 b**。让 q̇=0（无科氏离心），此时 b 应该只剩重力 g(q)：

```python
data.qpos[:] = some_pose
data.qvel[:] = 0.0
mujoco.mj_forward(model, data)
g_only = data.qfrc_bias.copy()     # q̇=0 → 只剩重力矩
# 与手算的重力矩对照（如单摆 θ=90° 时重力矩 = m·g·d·cos(θ)）
```

## 6.5 计算力矩控制的前置技能（阶段 6 预告）

计算力矩控制（CTC）公式：τ = M(q)·(q̈_des + Kp·e + Kd·ė) + b(q,q̇)

实现它需要的 MuJoCo 技能你 6.2~6.4 已全部掌握：

```python
M = np.zeros((model.nv, model.nv))
mujoco.mj_makeM(model, data)
mujoco.mj_fullM(model, data, M)
b = data.qfrc_bias.copy()

tau = M @ (qdd_des + kp*(q_des - data.qpos) + kd*(qd_des - data.qvel)) + b
data.ctrl[:] = tau          # motor 执行器：ctrl 即力矩
```

**注意**：`qfrc_bias` 含接触相关项（有接触时），CTC 实验建议从无接触的 2 连杆臂开始，人形站立（阶段 6）用接触时 b 也包含接触贡献——调试时先关重力（`gravity="0 0 0"`）分段验证。

## 6.6 接触力：mj_contactForce（阶段 6 站立的必备读数）

```python
mujoco.mj_forward(model, data)          # 接触在 forward/step 中求解
print("接触对数量:", data.ncon)

for i in range(data.ncon):
    c = data.contact[i]                 # 第 i 个接触的信息
    print(f"geom{c.geom1} <-> geom{c.geom2}, 穿透深度 {c.dist:.6f}")
    force = np.zeros(6)
    mujoco.mj_contactForce(model, data, i, force)   # 6D: 力(3) + 力矩(3)
```

**实测验证**：1kg 球静置地面，法向力 ≈ 9.8N（接触力包含弹簧阻尼的瞬态成分，球落地瞬间可能 18N+，稳定后回到 mg）。

**阶段 6 的用处**：
- 判断"站稳了"：两脚接触力之和 ≈ mg，且各支撑点力为正。
- 走路分析：脚底压力中心（CoP）——用 `c.pos`（接触点位置）加权平均。
- 阻抗控制：期望接触力 vs 实际接触力反馈。

## 6.7 其他动力学接口（按需）

```python

```

## 6.8 本章小结：阶段 5 实验的 MuJoCo API 对照表

| 你手写的 | MuJoCo 真值 | 关键注意 |
|---|---|---|
| M(q) | `mj_makeM` + `mj_fullM(model, data, M)` | **3.11 新签名**；先 makeM/step |
| b(q,q̇) | `data.qfrc_bias` | q̇=0 时只剩重力项 |
| τ = M·q̈ + b | `data.qfrc_inverse`（`mj_inverse`） | 先 step 再 inverse |
| 重力矩 | q̇=0 时的 qfrc_bias | 符号按教材约定 |
| 接触力 | `mj_contactForce` | 瞬态 vs 稳态分清 |
